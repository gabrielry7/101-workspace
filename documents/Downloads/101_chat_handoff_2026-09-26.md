# 101 / UnoCeroUno — Chat Handoff

## Executive summary

This chat has been a **post-Day-21 repair + reality-testing campaign** for 101.

The original 30-day machine was meant to go:

```text
Discover businesses
→ Understand business
→ Understand market
→ Diagnose
→ Design optimal presence
→ Build/change it
→ Measure
→ Learn
```

We nominally reached Day 21, but a Reality Trial showed that the downstream machinery
(SiteSpec → compiler → generated site → QA) had advanced faster than the upstream information
artery. So **Day 22 was frozen** while we repaired evidence acquisition, identity, Truth,
Business Genome richness, prospecting, and customer-facing content.

Current high-level system:

```text
Google / Places
Website + crawl
Reviews
Instagram
WhatsApp
Overture / bulk business sources
        ↓
immutable evidence
        ↓
identity / ownership
        ↓
Truth
        ↓
Business Genome
        +
Market Context
        ↓
SiteSpec
        ↓
Compiler
        ↓
Generated Site
        ↓
Browser QA
```

The project is now materially stronger, but the current bottleneck is **not architecture**.
It is proving that the system can reliably turn real-world evidence into:

1. correct business understanding;
2. useful prospecting decisions;
3. substantive, safe customer-facing websites;
4. repeatable results across categories.

# 1. Bogotá Business Universe

We built a first unified Bogotá Business Universe.

Initial retained canonical cohort:

```text
396 canonical businesses
```

Targetability v1 classified them as:

```text
TARGET_NOW      254
TARGET_LATER     39
LOW_FIT          59
UNRESOLVED       44
──────────────────
Observed targetable total: 293
```

But inspection showed that the classifier was too coarse.

For example, all 254 `TARGET_NOW` businesses shared the same generic reason stack:

```text
BOGOTA_SCOPE_SUPPORTED
EVIDENCED_REACH_CHANNEL
COMMERCIAL_LISTING_OBSERVED
ACTIONABLE_DIGITAL_GAP_OBSERVED
ENOUGH_EVIDENCE_FOR_CONSERVATIVE_REASONING
```

And all 59 `LOW_FIT` businesses were classified only because of:

```text
NO_EVIDENCED_REACH_CHANNEL
```

That revealed a semantic problem:

```text
"No contact found"
≠
"bad fit"
```

Future targetability should separate:

```text
SCOPE
IDENTITY
FIT
REACHABILITY
DIAGNOSTIC COVERAGE
TRUTH READINESS
OPPORTUNITY
PRIORITY
```

rather than hiding them inside one label.

# 3. How Bogotá-wide discovery should work

We decided not to treat Google Places as a census.

Instead the smart architecture is:

```text
RUES / registry identities
+
Overture geographic candidates
+
existing adaptive grid / Places discovery
+
text/search/directory discovery
        ↓
canonical identity resolution
        ↓
Business + BusinessLocation
        ↓
coverage estimation
```

The existing competitor/grid search machinery is reusable here.

The long-term goal is not:

> “Google returned X businesses.”

It is:

```text
Observed businesses
+
independent discovery frames
+
overlap
+
coverage estimation
+
stratified targetability
→ defensible Bogotá market-size estimate
```

A citywide targetable estimate is **not yet statistically defensible**.

  - customer-mentioned offerings;

  - risks;
  - investigation candidates;
- semantic run states:
  - not run;
  - partial;
  - failed;
  - valid empty.

The old weaker attribution rules and parallel orchestrator were not blindly copied.

# 20. What should happen next

Do **not** design another Review Intelligence system.

The next meaningful action is:

```text
232 saved real review texts
        ↓
existing ReviewIntelligenceService
        ↓
existing semantic backend
+ business/category context
        ↓
exact quote validation
        ↓
deterministic vs semantic comparison
        ↓
human review of disagreements
```

No new review acquisition is required for this experiment.

Once a currently callable provider is authorized/configured:

1. run the semantic backend on the existing 232 texts;
2. compare deterministic vs semantic outputs;
3. put disagreements + uncertain cases into the human review UI;
4. label them;
5. measure actual semantic precision / coverage;
6. freeze Review Intelligence policy;
7. then test cross-vertical cohorts.

# 21. Main lessons

## Evidence states must remain distinct

```text
observation
≠
candidate
≠
corroborated relationship
≠
Truth
≠
rendered output
≠
customer-ready
```

## Websites cannot be the only source of offerings

A lot of valuable SMBs may have no usable website.

## Reviews are richer than reputation

They can expose:

```text
offerings
staff/providers
prices
payments
operations
booking friction
customer segments
use cases
complaints
strengths
```

## LLMs should interpret, not invent

Correct pattern:

```text
full review
+ business/category context
→ LLM interpretation
→ exact source quote
→ deterministic validation
→ typed evidence
```

## Institutional memory is now mandatory

The project became large enough that capability rediscovery itself became an engineering cost.
