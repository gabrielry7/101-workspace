# Primeras comprobaciones, conservadas

1. La primera proyección del nuevo escenario pasó el objeto PlannerResult completo a `projectContent`; el validador rechazó `status/requirements/diagnostics` como campos ajenos al bundle. Se corrigió el consumidor para pasar únicamente input/profile/capabilities/plan. No se relajó el contrato.
2. Un comando npm directo no encontró Node en PATH; los runners compartidos usan el Node portable y su PATH explícito. Check posterior: 0 errores/warnings/hints; build 128 páginas.
3. `qa-01` y `qa-02` conservan capturas/fallos. El audit inicial comparó proporciones contra `naturalWidth/naturalHeight` de srcset, que Chromium devuelve corregidos por densidad y redondeados (p. ej. el WebP 640×427 se observa 620×413 con sizes=620). La geometría real mantiene la proporción del archivo; el auditor ahora la compara con las dimensiones inspeccionadas del archivo servido, cuyo SHA también se verifica. No crop ni cambio de tolerancia.
4. Ambas corridas se detuvieron en la activación de summary con Enter. Un probe separado sobre la misma página local confirmó foco SUMMARY y keydown/keyup, sin evento click. Al incluir el carácter Enter `text:'\r'` en CDP, Chromium emite click/toggle y cierra el details; ratón también lo alterna. Se corrige la síntesis de teclado del harness, no se agrega un manejador JS para sustituir el comportamiento nativo. El probe temporal no se entrega ni contiene secretos.

Las capturas iniciales son páginas completas de escenario ficticio; todavía no implican aceptación humana o PASS final. Los archivos B2, permisos y fixtures históricos no se modificaron.

5. La revisión de qa-03 detectó proximidad excesiva entre 01/04 en móvil y una portada desktop de 640px ampliada. Se mejora Stage con título/copy emparejados, se selecciona 1280px para portada desktop, se declaran slots/orden de carta y se respeta color-scheme oscuro en controles nativos. Las dos versiones anteriores de propuestas/contexto se archivan; no se sobrescribe un resultado aprobado.
6. La validación de bindings detectó referencias editoriales de borrador `online_order`/`reservation_request`, ajenas al catálogo B1. Se corrigen a `cart`/`booking` y se añade rechazo de IDs inexistentes. No se alteran capacidades H2 o catálogo histórico. qa-04 conserva su fallo de lectura CDP; qa-05 espera loadingFinished y aumenta sólo el buffer de lectura para las ocho reproducciones, manteniendo comparación SHA exacta.

La primera copia aislada pasó todos los comandos, con el único fallo de tests H8 conocido, pero falló al final en la nueva preservación B3: `.gitattributes` y `scripts/b2-demo-video.py` se habían tratado erróneamente como binarios. Git archive normaliza sus saltos de línea. Se conserva el primer recibo y la corrección de la política nueva B3 a LF para esos dos textos, comprobando primero sus hashes originales. No se sobreescribe código en la copia, no se cambia la preservación B2 ni se aflojan sus pins. La segunda materialización contiene la política corregida; sólo aplica los siete overlays de documentación histórica ya fijados por B2.

8. La primera QA aislada pudo observar una respuesta abortada de la página anterior: al cambiar viewport antes de navegar, Chromium solicita otra rendition responsive. Se filtran respuestas por `loaderId` del documento actual, no sólo por URL. qa-06 y la siguiente QA aislada pasan con HTML/DOM iguales; pequeñas diferencias de píxeles se localizan dentro de controles nativos de vídeo, sin máscaras.
9. Un probe posterior midió un fallo real no cubierto por el gate anterior: poster de vídeo 640×427 y clip 640×360 provocaban un salto de 67px al reproducir. La segunda reparación visual compartida reserva 16:9 y contiene el poster completo, sin recortar o modificar sus bytes. qa-08 comprueba ancho/alto estables antes/después del play en las ocho vistas. qa-07 conserva su fallo al intentar leer un rango de vídeo pausado/abortado como archivo completo. Se separa playback real de una petición local explícita de QA que obtiene el archivo entero y verifica su SHA mediante WebCrypto; no se atribuyen esos bytes a una transferencia normal completa ni a la carga inicial.
